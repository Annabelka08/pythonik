## Пояснения для защиты

### Выбор `and` / `or`

- **`and`** используется, когда условие должно выполняться **одновременно** по всем осям. Для прямоугольника точка внутри только если **и** `x` в диапазоне, **и** `y` в диапазоне: `0 <= x <= 5 and 0 <= y <= 3`.
- **`or`** использовался бы, если достаточно попасть хотя бы в одну область — здесь это неверно: точка с `x=2, y=10` не внутри, хотя `x` подходит.
- В варианте 5 `or` не нужен: категория определяется одним числом, достаточно цепочки `if/elif/else`.
- Для проверки «вне диапазона» удобно `value < 0 or value > 100` — здесь `or` корректен, так как достаточно выхода хотя бы с одной стороны.

### Порядок ветвей

- В `minimum.py` сначала проверяется первый кандидат, затем второй, затем третий — порядок задаёт приоритет при равенстве: при равных числах сработает **первая** подходящая ветвь, и результат всё равно корректный.
- В `calculator.py` **деление проверяется до самого деления**: ветвь `elif op == "/" and b == 0` идёт раньше `elif op == "/"`, иначе произошла бы ошибка `ZeroDivisionError`.
- В `variant.py` проверка диапазона (`if value < 0 or value > 100`) стоит **первой**, затем пороги идут по возрастанию: 0–24, 25–74, 75–100. Так границы не пересекаются и каждое значение попадает ровно в одну ветвь.

### Поведение при равенстве значений

- В `minimum.py` при равных числах (например, `5, 5, 5`) первая ветвь `if a <= b and a <= c` срабатывает и возвращает `5` — это корректно, так как все три равны.
- Если равны только два числа (`5, 5, 9`), первая ветвь ловит `a <= b and a <= c` → `5` — тоже верно.
- При равенстве на границах в `variant.py` (например, `25`, `75`) значение попадает в **старшую** категорию, потому что проверка идёт по возрастанию и первая подходящая ветвь уже не срабатывает: `25` не `< 25`, но `<= 74` → «Достаточно». Это соответствует условию «интервалы включают указанные концы».
- В `calculator.py` равенство операндов не влияет на выбор операции — ветвление идёт по символу, а не по значениям.
