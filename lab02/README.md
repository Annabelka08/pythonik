## 3. Предскажите результат

### Прогноз vs Python

| Выражение | Прогноз | Python | Совпало? |
|-----------|---------|--------|----------|
| `2 + 3 * 4` | 14 | 14 | ✅ |
| `(2 + 3) * 4` | 20 | 20 | ✅ |
| `17 // 5` | 3 | 3 | ✅ |
| `17 % 5` | 2 | 2 | ✅ |
| `-7 // 2` | **-4** | **-4** | ✅ |

### Различия и объяснение

Расхождений с корректным прогнозом нет. Но по `-7 // 2` есть **типичная ловушка интуиции**:

- Многие ожидают `-3`, мысленно «отбрасывая дробную часть» от `-3.5`.
- Python округляет **вниз, к −∞** (floor), поэтому `-7 // 2 = -4`.
- Причина — сохранение тождества `a = (a // b) * b + a % b`:
  `(-4) * 2 + 1 = -7` ✔
- В C/C++/Java целочисленное деление усекает к нулю и дало бы `-3`.

## Объяснения ключевых понятий

### Отличие `/` от `//`

- **`/`** — обычное деление, результат **всегда `float`**: `17 / 5 = 3.4`.
- **`//`** — целочисленное деление с округлением **вниз (floor)**: `17 // 5 = 3`, `-7 // 2 = -4`.
- `//` не «отбрасывает дробную часть», а именно округляет к меньшему целому. При положительных числах это выглядит как отбрасывание, при отрицательных — нет.
- В задачах `//` применяется там, где нужно **целое количество полных единиц** (часы, команды, упаковки).

### Смысл остатка (`%`)

- Остаток — это то, что «не поместилось» в целое число единиц: `a = (a // b) * b + a % b`.
- Пример: `23 % 5 = 3` — после формирования 4 полных команд по 5 человек остаётся 3 человека.
- Знак результата `%` в Python совпадает со знаком **делителя**: `-7 % 2 = 1`, `7 % -2 = -1`.
- Остаток `0` означает, что деление точное — все единицы заполнены полностью.

### Почему форматирование не устраняет неточность `float`

- Числа с плавающей точкой (`float`) хранятся в двоичном формате и не могут точно представить многие десятичные дроби (например, `0.1`, `0.2`, `2.5` в некоторых случаях).
- Пример: `0.1 + 0.2 = 0.30000000000000004`, а не `0.3`.
- Форматирование `f"{x:.2f}"` **меняет только отображение**, но не само значение: `f"{0.1 + 0.2:.2f}"` даст `"0.30"`, но внутри останется `0.30000000000000004`.
- Если после форматирования выполнить ещё вычисления, накопленная погрешность сохранится и может проявиться.
- Вывод: форматирование улучшает **вид**, но не **точность**. Для точных денежных расчётов используют `Decimal` или работу в копейках (целых числах).
