# Лабораторная работа: файлы и матрицы

## Формат входного файла `matrix.txt`

- Кодировка: UTF-8.
- Первая строка: два положительных целых числа — количество строк и столбцов.
- Далее ровно указанное количество строк, в каждой ровно указанное количество целых чисел, разделённых пробелами.
- Лишние и пустые строки считаются ошибкой.
- Один обычный перевод строки после последней строки данных допустим (это стандартное окончание файла).

## Обязательные задания

### 1. Надёжный ввод размера
`read_positive_integer()` в `main.py` повторяет ввод, пока не получит целое число > 0.
Различает сообщения:
- «не целое число» — если `int()` не сработал,
- «должно быть больше нуля» — если число ≤ 0.

Проверка последовательности `abc, 0, -2, 3`:
- `abc` → «не целое число»
- `0` → «должно быть больше нуля»
- `-2` → «должно быть больше нуля»
- `3` → принято, возврат 3

### 2. Чтение таблицы
`read_matrix(path)` в `files_lab.py`:
- Пустой файл → `ValueError("Файл пустой")`.
- Неверный заголовок → `ValueError` с указанием «Строка 1».
- Нечисловая ячейка → `ValueError` с указанием строки и столбца.
- Неправильное количество строк или чисел в строке → `ValueError` с номером строки.
- Отсутствие файла → `FileNotFoundError` (пробрасывается из `open`).

### 3. Отчёт
`main.py`:
1. Читает `matrix.txt` и обрабатывает все возможные ошибки.
2. Считает суммы строк, столбцов и результат варианта.
3. **Только после успешной проверки** открывает `report.txt` для записи.

Пример отчёта:
```
Суммы строк: 2 -2
Суммы столбцов: 5 -2 -3
Результат варианта: -3
```

## Индивидуальный вариант 5

**Условие:** сумма элементов, кратных 3.

Для `matrix.txt` с содержимым `[[1, -2, 3], [4, 0, -6]]`:
- `3 % 3 == 0` ✓
- `0 % 3 == 0` ✓
- `-6 % 3 == 0` ✓
- Сумма: `3 + 0 + (-6) = -3`.

Функция `selected_sum(matrix)` в `files_lab.py`. При отсутствии подходящих элементов возвращает 0.

## Ответы на вопросы

### Чем отличаются ошибки формата от ошибок доступа?

- **Ошибки формата** (`ValueError`) — файл существует и доступен, но его содержимое не соответствует ожидаемой структуре (неверный заголовок, нечисловые значения, неправильное количество строк/столбцов). Это проблема **данных**, и мы можем сообщить пользователю конкретную строку, где обнаружена ошибка.
- **Ошибки доступа** (`FileNotFoundError`, `PermissionError`, `OSError`) — файл нельзя открыть: его нет, нет прав, диск недоступен. Это проблема **среды**, и мы не можем анализировать содержимое.

Разделение важно для диагностики: в первом случае нужно исправить файл, во втором — проверить путь, права, доступность диска.

### Почему отчёт открывается для записи после проверки входа?

Если открыть `report.txt` для записи до проверки, и проверка упадёт, файл уже будет **обнулён** (режим `"w"` очищает файл при открытии). Пользователь потеряет предыдущий отчёт.

Правильный порядок:
1. Прочитать и проверить входные данные.
2. Выполнить все вычисления.
3. **Только если всё прошло успешно** — открыть отчёт для записи.

Так при ошибке существующий `report.txt` остаётся нетронутым.

### Проверка сохранности старого отчёта

Вручную проверено:
1. Создаём `report.txt` с произвольным содержимым.
2. Портим `matrix.txt` (например, пишем «abc»).
3. Запускаем `main.py` — программа сообщает об ошибке формата.
4. Содержимое `report.txt` **не изменилось**.

Результат: старый отчёт сохранён.

## Дополнительное задание: экспорт в CSV

Функция `export_to_csv(matrix, path)` использует стандартный модуль `csv.writer`.
Нельзя разбирать CSV вручную через `split(",")`, потому что значения могут содержать:
- разделители (запятые внутри кавычек),
- кавычки (экранируются удвоением),
- переносы строк.

`csv.writer` корректно обрабатывает все эти случаи.
